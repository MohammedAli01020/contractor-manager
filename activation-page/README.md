# صفحة تفعيل مدير الشركة

صفحة ثابتة (HTML/CSS/JavaScript) يمكن استضافتها مجانًا على Cloudflare Pages، ولا تحتاج إلى Node.js أو build command.

## قبل النشر

1. افتح `config.js`.
2. استبدل `https://REPLACE-WITH-YOUR-RAILWAY-DOMAIN` بعنوان HTTPS العام لخدمة الـ Backend على Railway، دون شرطة مائلة في النهاية.
3. تأكد أن الـ Backend يسمح بطلبات CORS من نطاق صفحة التفعيل، وأن عنوان الواجهة مسموح به في إعدادات CORS الحالية. لا تفتح CORS لكل المواقع في الإنتاج.
4. اضبط `app.platform.activation-base-url` على عنوان صفحة التفعيل المنشورة، مثل:
   `https://your-project.pages.dev/index.html`
   سيضيف الـ Backend الرمز في query parameter باسم `token`.
5. اختبر رابطًا صالحًا، ورابطًا منتهيًا، ورمزًا مستخدمًا سابقًا.

## النشر على Cloudflare Pages

1. ارفع المستودع إلى GitHub (الصفحة موجودة في مجلد `activation-page`).
2. من Cloudflare Dashboard اختر **Workers & Pages → Create → Pages → Connect to Git**.
3. اختر المستودع والفرع المطلوب.
4. اجعل **Root directory** = `activation-page`.
5. اترك Build command فارغًا، ولا تحتاج إلى Build output generation؛ هذه ملفات ثابتة. إذا طلبت لوحة Cloudflare مجلدًا للإخراج، استخدم `.`.
6. انشر الصفحة واستخدم نطاق `pages.dev` المجاني الذي توفره الخدمة.

## ملاحظات أمنية

- لا تضع أسرار الخادم أو بيانات دخول في ملفات الواجهة؛ كل ما في هذه الملفات عام ويمكن لأي زائر قراءته.
- رمز التفعيل يظهر في الرابط الذي يستلمه الأدمن، ثم تحذف الصفحة الرمز من شريط العنوان بعد قراءته. لا تشارك الرابط إلا مع الأدمن المقصود.
- فعّل HTTPS، ولا تسجل الرمز أو كلمة المرور في سجلات الواجهة أو الخادم.
- صفحة الواجهة وحدها لا تجعل الـ Backend عامًا ولا تتجاوز سياسة CORS. يجب ضبط عنوان Railway وإعدادات CORS بشكل صحيح.
